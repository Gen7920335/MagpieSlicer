# Cura-Style Normal Support Generator Plan

This document defines how to add a Cura-style normal support generator to this OrcaSlicer fork.

Scope:
- Add a new normal support generation mode inspired by CuraEngine.
- Keep tree / organic support untouched.
- Keep the existing Orca/Prusa-derived normal support available as `Normal (Prusa style)`.
- Add a new selectable mode named `Normal (Cura style)`.

References:
- CuraEngine `src/support.cpp`: https://github.com/Ultimaker/CuraEngine/blob/main/src/support.cpp
- CuraEngine `src/infill.cpp`: https://github.com/Ultimaker/CuraEngine/blob/main/src/infill.cpp
- Orca normal support entry point: `src/libslic3r/Support/SupportMaterial.cpp`
- Orca normal support toolpath generation: `src/libslic3r/Support/SupportCommon.cpp`

## 1. Current Orca Normal Support

Current Orca normal support is generated by `PrintObjectSupportMaterial::generate()`.

Main flow:

1. `top_contact_layers()`
   - Detects overhang/contact polygons.
   - Uses Orca's `detect_overhangs()` and `detect_contacts()` logic.

2. `bottom_contact_layers_and_layer_support_areas()`
   - Projects top contacts downward.
   - Uses `project_support_to_grid()` and `SupportGridPattern`.
   - Produces per-layer support areas.

3. `generate_base_layers()`
   - Converts projected support areas into intermediate/base layers.
   - Trims them against object geometry.

4. `generate_interface_layers()`
   - Propagates top/bottom contact surfaces into interface layers.

5. `generate_support_layers()`
   - Installs support layers into `PrintObject`.

6. `generate_support_toolpaths()`
   - Converts `SupportGeneratorLayer` polygons into extrusion paths.
   - This is where support infill/interface patterns are applied.

Important behavior:
- Orca's support area generation is grid-projection based.
- `SupportGridPattern` can make support footprints look stepped, snapped, or expanded differently from a direct polygon propagation algorithm.
- Fill pattern changes do not change support area shape.

## 2. Cura Normal Support Algorithm

CuraEngine's normal support flow is centered around `AreaSupport`.

Main flow:

1. `generateOverhangAreas()`
   - Iterates model meshes.
   - Calls `generateOverhangAreasForMesh()`.

2. `generateOverhangAreasForMesh()`
   - Initializes per-layer overhang storage.
   - Calls `computeBasicAndFullOverhang()` per layer.

3. `computeBasicAndFullOverhang()`
   - Compares current layer outlines against outlines below.
   - Uses support angle and layer height to decide how far lower geometry may support the current layer.
   - Returns:
     - `basic_overhang`: strict area needing support.
     - `full_overhang`: expanded overhang, clipped to the current model outline, used for smoother joining.

4. `generateSupportAreas()`
   - Calls `generateSupportAreasForMesh()` for each mesh.
   - Unions mesh-local support areas into `global_support_areas_per_layer`.
   - Generates roof/bottom interface areas.
   - Splits global areas into support infill parts.

5. `generateSupportAreasForMesh()`
   - Runs top-down from high layers to low layers.
   - On each layer:
     - starts from overhang area above top Z distance,
     - expands support horizontally if configured,
     - unions with support from the layer above through `join()`,
     - subtracts model geometry from the current layer,
     - applies bottom Z distance / stair stepping through `moveUpFromModel()`.
   - After the top-down loop:
     - subtracts XY-disallowed areas,
     - removes unprintable small areas,
     - filters buildplate-only support,
     - enforces top Z distance,
     - removes floating support.

6. `join()`
   - The main top-down propagation operation.
   - Normally unions `supportLayer_this` with `supportLayer_up`.
   - Optional conical support offsets the upper support area before union.
   - Optional support join distance merges nearby support islands.

7. `generateSupportRoof()` / `generateSupportBottom()`
   - Builds interface areas from intersections between global support areas and nearby model outlines.
   - Calls `generateSupportInterfaceLayer()`.
   - Removes interface polygons from normal support areas.

Key difference from Orca:
- Cura's normal support area is direct polygon propagation, not Orca's support-grid extraction.
- The main support body is produced by top-down polygon union/subtraction.
- The support infill generator only fills areas after support areas are built.

## 3. Desired Orca UX

Change `support_type` labels and enum:

Existing values:
- `normal(auto)` -> `Normal (Prusa style, auto)`
- `normal(manual)` -> `Normal (Prusa style, manual)`
- `tree(auto)` -> `Tree (auto)`
- `tree(manual)` -> `Tree (manual)`

New values:
- `normal_cura(auto)` -> `Normal (Cura style, auto)`
- `normal_cura(manual)` -> `Normal (Cura style, manual)`

Recommended enum changes:

```cpp
enum SupportType {
    stNormalAuto,
    stTreeAuto,
    stNormal,
    stTree,
    stNormalCuraAuto,
    stNormalCura
};
```

Helper behavior:
- `is_tree()` must return true only for `stTreeAuto` and `stTree`.
- Add `is_normal_prusa()` for current Orca normal modes.
- Add `is_normal_cura()` for Cura-style normal modes.
- Add or update `is_auto()` so Cura-auto is treated as automatic support.

Do not rename serialized keys for existing values. Existing presets using `normal(auto)` and `normal(manual)` must continue to load.

## 4. Implementation Strategy

Do not replace the existing normal support generator in place first.

Add a parallel path:

```cpp
void PrintObjectSupportMaterial::generate(PrintObject &object)
{
    if (is_normal_cura(m_object_config->support_type.value)) {
        this->generate_cura_style(object);
        return;
    }

    this->generate_prusa_style(object);
}
```

Actual code should probably keep the current body of `generate()` as-is and extract it into `generate_prusa_style()` only if the diff stays manageable.

New files are preferred:
- `src/libslic3r/Support/CuraStyleSupport.hpp`
- `src/libslic3r/Support/CuraStyleSupport.cpp`

Primary class:

```cpp
class CuraStyleSupportGenerator
{
public:
    CuraStyleSupportGenerator(
        const PrintObject &object,
        const PrintConfig &print_config,
        const PrintObjectConfig &object_config,
        const SlicingParameters &slicing_params,
        const SupportParameters &support_params);

    void generate(
        PrintObject &object,
        SupportGeneratorLayerStorage &layer_storage,
        SupportGeneratorLayersPtr &raft_layers,
        SupportGeneratorLayersPtr &bottom_contacts,
        SupportGeneratorLayersPtr &top_contacts,
        SupportGeneratorLayersPtr &intermediate_layers,
        SupportGeneratorLayersPtr &interface_layers,
        SupportGeneratorLayersPtr &base_interface_layers);
};
```

## 5. Orca Data Mapping

| CuraEngine | Orca |
| --- | --- |
| `SliceDataStorage` | `PrintObject` plus `Layer` vector |
| `SliceMeshStorage::layers[layer].getOutlines()` | `object.layers()[i]->lslices` / `to_polygons(layer.lslices)` |
| `Shape` | `ExPolygons` / `Polygons` |
| `supportLayers[layer].support_roof` | `SupportGeneratorLayer` with `SupporLayerType::TopContact` or `TopInterface` |
| `supportLayers[layer].support_bottom` | `SupportGeneratorLayer` with `SupporLayerType::BottomContact` or `BottomInterface` |
| `global_support_areas_per_layer` | candidate `std::vector<Polygons>` or `std::vector<ExPolygons>` |
| `support_infill_parts` | not needed if reusing Orca `generate_support_toolpaths()` |

Use Orca polygon APIs:
- `union_`, `union_ex`
- `diff`, `diff_ex`
- `intersection`, `intersection_ex`
- `offset`, `offset_ex`
- `closing_ex`
- `opening` if available, otherwise offset-in/out equivalent

## 6. Minimal Cura-Style V1

The first useful implementation should be intentionally narrower than CuraEngine.

V1 supported:
- Automatic normal support.
- Manual support enforcers if they are already represented in Orca annotations.
- Top contact.
- Base/intermediate support body.
- Top interface through existing Orca `generate_interface_layers()` if possible.
- Existing Orca `generate_support_toolpaths()` for final extrusion.

V1 deferred:
- Cura support towers.
- Cura conical support.
- Cura gradual support infill.
- Cura support mesh modifier behavior.
- Cura roof/bottom exact fractional layer behavior.
- Cura cross-support provider.

Why:
- Orca already has support enforcer/blocker, interface, raft, infill, and extrusion infrastructure.
- The user-facing problem is current normal support area shape, not Cura's entire setting ecosystem.
- A limited polygon-propagation support body can be compared quickly against existing Orca normal support.

## 7. V1 Algorithm In Orca Terms

### 7.1 Precompute Layer Polygons

Build:

```cpp
std::vector<Polygons> model_polygons_by_layer;
std::vector<Polygons> model_polygons_xy_block_by_layer;
std::vector<Polygons> basic_overhang_by_layer;
std::vector<Polygons> full_overhang_by_layer;
std::vector<Polygons> support_body_by_layer;
```

For each object layer:
- `model_polygons_by_layer[i] = to_polygons(object.layers()[i]->lslices)`
- `model_polygons_xy_block_by_layer[i] = offset(model_polygons_by_layer[i], gap_xy_scaled)`

### 7.2 Compute Cura-Like Overhangs

Equivalent of Cura `computeBasicAndFullOverhang()`:

```cpp
max_dist = layer_height / tan(support_threshold_angle)
supported_below = union of lower layer outlines offset by max_dist
basic_overhang = current_layer_polygons - supported_below
full_overhang = offset(basic_overhang, max_dist * smoothing_layers + 0.1mm) intersect current_layer_polygons
```

Notes:
- Cura uses `support_angle`. Orca has `support_threshold_angle` and `support_threshold_overlap`.
- For V1, use Orca's existing `detect_overhangs()` if exact threshold behavior matters more than Cura parity.
- For closer Cura behavior, implement this independent comparison.

### 7.3 Top-Down Propagation

Loop from high layer to low layer:

```cpp
for layer i from top - top_z_gap_layers down to 0:
    layer_this = full_overhang_by_layer[i + top_z_gap_layers]

    if support_expansion > 0:
        layer_this = cura_style_horizontal_expansion(layer_this, model_polygons_by_layer[i])

    if i + 1 < layer_count:
        layer_above = support_body_by_layer[i + 1]
        layer_this = join(layer_above, layer_this)
        layer_this = diff(layer_this, model_polygons_by_layer[i])

    apply_bottom_gap_and_stairs(layer_this, i)
    support_body_by_layer[i] = layer_this
```

V1 `join()`:

```cpp
joined = union_(layer_this, layer_above)
if support_join_distance > 0:
    joined = offset(offset(joined, -half_min_feature_width), support_join_distance + half_min_feature_width)
    joined = offset(joined, -support_join_distance)
return joined
```

V1 can skip conical support initially.

### 7.4 Postprocess

For each layer:
- subtract `model_polygons_xy_block_by_layer[i]`
- close/open to remove too thin support:
  - `offset(..., -half_min_feature_width)`
  - `offset(..., +half_min_feature_width)`
- remove tiny support islands.
- if buildplate-only:
  - propagate from layer 0 upward by intersection with previous touching support.
- enforce top Z distance:
  - subtract model outlines at `i + top_z_gap_layers - 1`.
- remove floating support:
  - `support[i] = support[i] intersect union(support[i - 1], support[i + 1])`

### 7.5 Convert To Orca Support Layers

For every non-empty `support_body_by_layer[i]`:
- allocate `SupportGeneratorLayer` as `SupporLayerType::Intermediate` or `Base`.
- set:
  - `bottom_z`
  - `print_z`
  - `height`
  - `polygons`

Then create contact/interface:
- Best V1: derive `top_contacts` from `basic_overhang_by_layer`, using Orca's existing contact layer shape conventions.
- Reuse `generate_interface_layers()` with generated top/bottom contacts.
- Call `generate_support_layers()`.
- Call `generate_support_toolpaths()`.

## 9. Tests

Minimum test models:

1. 45-degree overhang block
   - Compare support outline against existing Prusa style.
   - Confirm top Z gap is preserved.

2. Sphere or curved underside
   - Check whether Cura-style propagation reduces grid-stepped support edges.

3. Bracket with inner cavity
   - Confirm support does not pass through model.
   - Confirm floating support cleanup works.

4. Buildplate-only scenario
   - Confirm disconnected upper support is removed.

5. Manual support enforcer/blocker scenario
   - Confirm blockers subtract support.
   - Confirm enforcers create support.

## 10. Known Risks

- Exact Cura behavior is not possible through direct copy because CuraEngine and Orca use different slice and settings structures.
- Cura's support roof/bottom generation should not be copied literally in V1; Orca already has mature interface layer and extrusion logic.
- Existing Orca presets must not break. Keep old serialized enum keys.
- `support_type` is used in GUI toggle logic. Every helper using `is_tree()` / `is_auto()` must be audited.
- Large C++ rebuilds are expected after changing `PrintConfig.hpp`.
